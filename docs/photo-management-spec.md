# 管理画面をEmDashへ一本化し、写真はOrganizer型で扱う

更新日: 2026-09-04
対象Issue: [#47](https://github.com/kanouk/kanouk.com/issues/47)
状態: 実装基準

## この改修で決めること

EmDashを唯一の管理画面とする。独立した「Studio」は廃止し、記事、固定ページ、写真、アルバムの保存先や公開場所を迷わない構造へ戻す。

写真とアルバムの主な操作は、WordPressのように1件ずつフォームで編集する方法ではなく、SmugMugのOrganizerを参考にした「写真を整理」画面へ集約する。EmDash標準のAlbum／Photo編集画面は、細かな項目を1件ずつ直す補助経路として残す。

この改修の適用時には、既存の写真データを一括更新せず、公開URLとデータ構造を維持する。日常操作で利用者が明示的に保存・公開した変更だけを反映する。管理画面の情報設計と操作フローを作り直す。

## 用語

| 用語 | この仕様での意味 |
|---|---|
| EmDash | 記事、固定ページ、写真、アルバム、原本ファイルを管理する唯一の管理画面 |
| 写真を整理 | EmDash内に置く写真専用画面。SmugMugのOrganizerに相当する日常作業の入口 |
| Album | アルバム名、説明、カバー、公開状態と、所属する写真のまとまり |
| Photo | 公開サイトへ表示する1枚の写真と、そのタイトル、キャプション、代替テキストなどの情報 |
| Media | アップロードした画像や動画の原本ファイル |
| Studio | 廃止する旧管理画面の名称。改修後の画面名やナビゲーションには使わない |

## SmugMugから採用する考え方

SmugMugではGalleryが写真の置き場所になり、OrganizerでGalleryを選んだまま、アップロード、複数選択、ドラッグによる並べ替え、移動、写真情報の一括編集を行える。この仕様ではSmugMugのGalleryを既存のAlbumに対応させる。Gallery設定は同じ管理環境から開けるが、写真整理とは役割が分かれている。

今回採用する要素は次のとおり。

- 選択中のアルバムが常に分かる
- アルバムを選ぶと、その写真がすぐ中央へ表示される
- 選択中のアルバムへ直接アップロードできる
- サムネイルを主情報にし、ファイル名は補助情報にする
- 1枚選択と複数選択で、利用できる操作を切り替える
- ドラッグと矢印の両方で並べ替えられる
- 写真を選んだまま、キャプションなどを編集できる
- アルバムの公開ページを1操作で確認できる

参考にしたSmugMug公式情報:

- [Upload photos and videos](https://www.smugmughelp.com/hc/en-us/articles/18212780494868-Upload-photos-and-videos)
- [Organize with folders and hierarchy](https://www.smugmughelp.com/hc/en-us/articles/18212469747604-Organize-with-folders-and-hierarchy)
- [Add photo titles, captions, and keywords](https://www.smugmughelp.com/hc/en-us/articles/18212448992660-Add-photo-titles-captions-and-keywords)
- [Create a gallery](https://www.smugmughelp.com/hc/en-us/articles/18212798551572-Create-a-gallery)
- [Change settings for a gallery, folder, or page](https://www.smugmughelp.com/hc/en-us/articles/18212440954772-Change-settings-for-a-gallery-folder-or-page)

SmugMugには同じ写真を複数Galleryへ表示するCollect機能もあるが、今回は導入しない。現在のPhotoは1つのAlbumへ所属する設計であり、複数所属を追加すると公開ページ、並び順、移行データを含むスキーマ変更が必要になるためである。今回は「別アルバムへ移動」とする。

## 管理画面はEmDashだけにする

改修後の構成は次のとおり。

```text
EmDash
├─ Posts                 記事を編集
├─ Pages                 固定ページを編集
├─ Albums                アルバム情報を1件ずつ編集
├─ Public Photos         写真情報を1件ずつ編集
├─ 写真を整理            アルバムと写真の日常作業
└─ Media                 原本ファイルの一覧と基本情報

公開サイト
└─ 閲覧と表示確認のみ
```

「写真を整理」はEmDash内の写真専用ツールであり、別のCMSではない。記事、固定ページ、Media、要確認などを重複実装しない。

ユーザー向けの画面名、ナビゲーション、説明文から「Studio」を外す。ソースコード内部の既存ディレクトリ名やAPI名は、無理な一括改名で回帰を増やさない範囲で整理する。

## 各画面の責務を重ねない

| 画面 | 主に行うこと | 行わないこと |
|---|---|---|
| Posts | 記事の作成、本文、画像、分類、公開 | 写真アルバムの整理 |
| Pages | 固定ページの作成、本文、SEO、公開 | 写真アルバムの整理 |
| Albums | アルバム名、説明、撮影期間、カバー、表示設定などの詳細編集 | 大量写真の一覧整理 |
| Public Photos | 1枚の写真を詳細に編集 | アルバム全体の整理 |
| 写真を整理 | アルバム選択、写真追加、複数選択、並べ替え、移動、写真情報、まとめて公開 | 記事、固定ページ、Media削除 |
| Media | 原本ファイルの一覧と基本情報の確認 | 日常の写真編集、重複・参照元の診断 |
| 公開サイト | 公開結果の閲覧 | 下書き編集、公開操作 |

同じ項目を複数画面から変更できる場合でも、主画面を明示する。アルバム単位の日常作業では「写真を整理」を主画面とし、標準編集画面へのリンクは「詳細編集」と表記する。

## 「写真を整理」画面

### 全体配置

デスクトップでは3領域に分ける。

```text
┌────────────┬────────────────────────┬──────────────┐
│ アルバム   │ 写真グリッド           │ 写真情報     │
│ 検索       │ 操作バー               │ タイトル     │
│ 一覧       │ サムネイル             │ キャプション │
│ 新規作成   │ 複数選択・並べ替え     │ alt・撮影日  │
└────────────┴────────────────────────┴──────────────┘
```

モバイルでは上段のタブで「アルバム」と「写真」を切り替え、写真側では「写真」と「写真情報」を切り替える。写真グリッドを最初に表示し、選択中のアルバム名と公開操作はスクロール中も上部へ固定する。

### アルバム領域

各アルバムに次を表示する。

- カバー写真
- アルバム名
- 写真点数
- 下書きまたは変更ありの写真点数
- アルバムの公開状態

操作:

- アルバム名で検索
- アルバムを選択
- 新しいアルバムの下書きを作成
- 標準のAlbum詳細編集を開く
- Album公開ページを開く

新規作成後は作成したアルバムを自動選択し、そのまま写真を追加できる状態にする。

アルバムの切り替えは、保存や公開などの処理中は無効にする。未保存の入力がある場合は確認を表示し、破棄を選んだ場合だけ切り替える。

### 写真グリッド

写真カードには次を表示する。

- 320px派生サムネイル
- タイトルまたはキャプション
- 撮影日
- 下書き／公開済み／変更あり
- キャプションなし、altなし、位置情報ありの要確認表示
- カバー写真の表示
- ファイル名は必要時だけ確認できる補助情報

操作:

- 1枚選択
- 複数選択、表示中の写真の全選択、選択解除
- 最大20枚を一度にアップロード
- ドラッグによる並べ替え
- 前後ボタンによる並べ替え
- 撮影日順に整列
- カバー写真に設定
- 別アルバムへ移動
- 直前の並べ替えと移動を取り消す
- Photo公開ページまたはPhoto詳細編集を開く

カード本体を押すと、その1枚だけを編集対象にし、それまでの複数選択は解除する。チェックボックスは一括操作の対象を選ぶために使う。チェックが1枚だけならその写真の情報を表示し、2枚以上なら一括操作へ切り替える。

要確認フィルターは「キャプションなし」「altなし」「保存データ内に位置情報あり」「原本の位置情報未確認」「未公開」を1条件ずつ選ぶ。検索とフィルターは併用できる。`表示中を全選択`は、選択Albumの全Photoを読み終えた後にだけ利用でき、その時点で検索と要確認フィルターの両方に一致している写真を対象にする。

旧StudioにあったSHA、参照元、未使用ファイル、重複候補の診断画面は削除する。標準のEmDash Mediaはこれらを表示しないため、本改修では移管扱いにしない。Mediaの原本一覧と基本情報だけを残し、整合性診断が再び必要になった場合は、日常の写真編集と混ぜず、EmDash内の読み取り専用機能として別Issueで設計する。

撮影日順は古い写真から並べ、タイムゾーン付き日時は同じ時刻へ換算して比較する。撮影日がない写真は末尾に置き、同じ日時では現在の並び順と内部IDで順序を固定する。デスクトップはドラッグ、キーボードはカード上でAltキーと矢印キー、タッチ端末はカード下の前後ボタンで並べ替える。

アップロード先は常に選択中のアルバムとする。受け付ける形式はJPEG、PNG、WebP、GIF、AVIFで、1枚50MBまで、一度に20枚までとする。SVG、HEIC、その他の形式は対象外とする。21枚以上を選んだ場合、未対応形式、上限を超えた写真は、対象外になったファイル名と理由を表示する。タイトルと代替テキストの初期値は拡張子を除いたファイル名、キャプションと撮影日は空欄、並び順はアルバム末尾とする。

Mediaを先に保存し、その後にPhotoの下書きを作る。Photo作成だけが失敗した場合、アップロード済みのMediaは自動削除せず、EmDashのMediaから確認できる状態で残す。成功した写真は取り消さず、失敗したファイルだけを表示する。アップロード中はアルバム切り替えと別の更新操作を無効にする。

### 写真情報

1枚だけ選択した場合、右側で次を編集する。

- タイトル
- キャプション
- 代替テキスト
- 撮影日
- 所属アルバム

保存は`下書き保存`を押した時点で行う。入力を変えた直後は`未保存`と表示する。未保存中は、個別公開、まとめて公開、並べ替え、カバー変更、一括操作を無効にする。別の写真、別のアルバム、詳細編集、公開サイトへ移る場合は確認を表示し、意図しない破棄を防ぐ。保存中、保存済み、競合、失敗を区別し、競合や失敗が起きても入力内容は画面に残す。

アルバム名と説明も明示的に下書き保存できる。まとめて公開を押した場合は、未保存のアルバム名と説明を先に下書きへ保存する。その保存に失敗したら、写真の公開を始めない。

複数選択時は次を一括変更できる。

- キャプション
- 代替テキスト
- 所属アルバム
- 公開

テキスト変更は「上書き」「先頭へ追加」「末尾へ追加」を選ぶ。「上書き」は選択したすべての写真を同じ内容へ置き換えるため、実行前に対象数を含む確認を表示する。追加モードでは入力した前後の空白を保持する。処理中は選択対象を固定し、部分失敗時は失敗した写真だけを選択状態に残す。

### 公開の単位

「写真を整理」画面には、選択中アルバムに対する主ボタンを1つだけ置く。

- 初回公開前: `アルバムを公開`
- 公開後に変更がある場合: `変更を公開`
- 公開する変更がない場合: `公開済み`

公開対象は次のとおり。

1. 選択中Albumの下書き
2. 選択中Albumに現在所属する、未公開または変更ありのPhoto
3. 今回の操作で別Albumへ移動したPhoto

写真の所属先はPhotoが持っている。公開済みAlbum Aから公開済みAlbum Bへ移したPhotoを公開すると、Album Aの公開ページから外れ、Album Bの公開ページへ加わる。Album Aから下書きのAlbum Bへ移した場合は、Photoを公開するとAlbum Aから外れるが、Album Bを明示的に公開するまではAlbum Bの一覧に現れない。移動先Albumは自動公開しない。移動した写真が移動元Albumのカバーでも、カバー画像は自動変更しない。カバーは写真の所属とは別の画像参照であり、利用者が別の写真を明示的に選ぶまで維持する。公開後は移動元と移動先のキャッシュを無効化し、次回取得から新しい所属を反映する。

公開処理はPhotoを先に、選択中のAlbumを最後に行う。一部失敗した場合、成功した公開は戻さない。完了とは表示せず、成功件数、失敗件数、Albumを含む失敗対象と理由を表示する。再実行時は未公開の対象だけを処理する。公開による既存のキャッシュ無効化を利用し、移動元と移動先の次回取得へ新しい所属を反映する。

並べ替えは対象写真すべての下書き保存が成功した場合だけ完了とする。途中で失敗した場合は、同じ処理で保存できた写真を元の位置へ戻し、位置の重複を残さない。復元にも失敗した写真があれば、その写真と理由を表示して再確認を求める。写真移動と一括テキスト編集では成功分を保持し、失敗分だけを選択状態に残す。

標準のAlbum／Photo編集画面にある公開機能も利用できるが、写真整理画面では上記の一括公開を通常経路として案内する。Organizerから追加され、位置情報が未確認のPhotoは、どの管理画面から操作しても共通APIが公開と公開予約を拒否する。

## AlbumsとPublic Photosの標準画面

### Albums一覧・編集

- Album編集画面に、写真点数と状態別件数を表示する
- 最大24点のサムネイルを表示する
- `写真を整理`で、対象Albumを選択したOrganizerを開く
- `公開ページを表示`で対象アルバムを開く
- Album標準フォームは詳細編集として維持する

### Public Photos一覧・編集

- 一覧にサムネイル、タイトル／キャプション、所属アルバム、要確認、状態／更新日を表示する
- Photo標準フォームは1枚の詳細編集として維持する
- 対象Photoから、所属Albumを選択したOrganizerを開ける
- 内部項目が表示されても、通常経路では「写真を整理」を先に案内する

## 公開サイトは閲覧専用へ戻す

現在の公開写真サイトには、管理セッションを持つ場合だけ現れる編集バーと、Album／Photoの編集パネルがある。これはEmDashと重複するため削除する。

- 公開サイトは認証状態に関係なく同じ閲覧画面を返す
- 公開写真ホストでは管理APIを404にし、管理画面へのアクセスはブログ側のEmDashへ転送する
- 公開確認はEmDashから対象URLを新しいタブで開く
- 旧管理画面用Cookieと引き継ぎ用tokenを認証に使わない。残存Cookieが送られても無視する
- 公開ページのキャッシュ分離、ホスト分離、レスポンシブ画像は維持する

同じWorkerがブログと写真サイトを配信するため、ホストと経路の組み合わせを次のように制限する。

| ホストと経路 | 動作 |
|---|---|
| `blog.kanouk.com/_emdash/admin/*` | EmDash管理画面を表示 |
| `blog.kanouk.com/_emdash/api/*` | EmDashの認証と権限確認後に利用 |
| `photos.kanouk.com/_emdash/admin/*` | 同じ経路の`blog.kanouk.com`へ転送 |
| `photos.kanouk.com/_emdash/api/media/file/*`のGET／HEAD | 未削除・公開中のlive revisionが参照し、新規アップロードなら位置情報確認済みである原本だけ読取を許可。それ以外は404 |
| 上記以外の`photos.kanouk.com/_emdash/*` | 404を返す |
| stagingのブログ・写真ホスト | 本番と同じ規則をstaging同士で適用 |

削除する`/studio/handoff`と`/studio/api/*`は転送せず404を返す。旧ブックマークから誤って別の編集画面へ入らないようにする。

## データと安全性

- Mediaは原本、Photoは公開写真情報、Albumは写真のまとまりという既存モデルを維持する
- Photoは1つのAlbumへ所属する
- OrganizerからMediaやPhotoを完全削除しない
- 8MB以下の画像はEmDashが計算する`sha1:`形式のcontent hashで同一Mediaを再利用する。8MBを超える画像は現在のEmDashではクライアント側hashを作らないため、この経路では重複を自動判定しない
- 一覧では原寸画像を取得しない
- 更新時は保存時点の版を照合し、別画面の更新が先にあれば上書きせず再読込を求める
- 一括処理は成功と失敗を分け、操作レシートを残す
- `位置情報あり`はPhotoの緯度・経度・高度、または保存済みの移行メタデータ内に位置情報がある場合に表示する。新規アップロードした原本EXIFはOrganizerでは未検査として扱い、`原本の位置情報未確認`を表示する
- Organizerから新規アップロードしたPhotoは、原本の位置情報確認が完了するまでOrganizerの個別公開・一括公開を無効にする。さらに共通APIで公開と公開予約を拒否し、標準Photo編集からも安全条件を迂回できないようにする。写真ホストの原本経路でも、未削除・公開中のlive revisionと確認状態を照合し、削除済み、下書き、未確認、参照されていないstorage keyは404にする
- 自動再エンコードで写真全体を変更せず、既存の明示allowlist方式で対象Photoだけを処理する。CMSの緯度・経度・高度と埋め込みGPSを除去し、公開／非公開の状態を維持した読戻しに成功した時点で`確認済み`と記録する
- 派生画像変換に失敗した場合は原本へフォールバックせず、エラーを返す

## 大量データの扱い

- Album一覧の取得が終わった時点で画面を表示し、全Photoの読込完了を待たせない
- Photoの索引は100件ずつ読み、Albumごとの点数と変更件数を段階的に更新する
- 読込中は`写真件数を読み込み中`と表示し、0件と確定したように見せない
- 選択中AlbumのPhotoは、Albumを選ぶたびにAlbum条件で別途全件取得する。再訪時も以前の完了状態を使い回さず、取得が完了するまでアップロード、並べ替え、移動、一括編集、公開を無効にする。これにより末尾位置の誤判定、positionの衝突、未読込Photoを残した公開を防ぐ
- サムネイルは320pxを基本とし、一覧で原寸画像を取得しない
- 同じ画面を開いたまま保存した内容が、遅れて届いた古い索引データで上書きされないよう、更新日時が新しいデータを優先する
- 数千点規模での起動を前提とし、全件を一つの応答へまとめない。将来1万点規模で操作遅延が確認された場合は、サーバー側のAlbum別件数集計とグリッド仮想化を別Issueで追加する

## 影響範囲

### 管理UI

- EmDash内の追加ページを7画面から`写真を整理`の1画面へ縮小
- EmDashへの追加機能は写真一覧の列、Album／Photoの案内パネル、Organizerに限定
- 既存のStudio用CSSをOrganizer向けに整理

### 公開サイト

- 写真レイアウトから管理コンポーネントを除去
- 管理セッションCookieをキャッシュ判定から除去
- `/studio/handoff`と`/studio/api/*`を除去
- 写真ホストでは公開Media読取以外の`/_emdash/*`を転送または拒否
- 匿名HTML、URL、SEO、写真表示には変更を加えない

### API

- EmDash Content／Media APIアダプターはOrganizerで再利用
- 記事、固定ページ、Media利用状況専用のStudio関数は削除
- 操作レシート用のEmDash内APIは維持

### ドキュメント・テスト

- Studioを前提にした契約テストを、単一管理画面とOrganizerの契約へ変更
- 公開管理セッションのテストを削除
- 写真の並び順、一括編集、競合、派生画像、安全な位置情報除去のテストを維持
- `docs/studio-architecture.md`を廃止し、本書を正本とする

## 対象外

- 1枚のPhotoを複数Albumへ所属させるCollect機能
- SmugMugのFolder階層
- 写真販売、透かし、パスワード共有
- AIによる自動分類や自動削除
- Mediaの完全削除
- SHA、参照元、未使用ファイル、重複候補を確認する高度なMedia診断
- 公開サイトのデザイン変更
- 記事本文エディタの再実装

## 受け入れ条件

- 管理画面の入口がEmDashだけになる
- ユーザー向けの独立Studioナビゲーションがなくなる
- アルバムを選ぶと、その写真がサムネイルグリッドで表示される
- 選択中アルバムへ20枚を一度にアップロードでき、21枚目以降と50MB超を理由付きで除外する
- 写真を見ながらキャプション、alt、撮影日を編集できる
- マウス、キーボード、タッチで写真を並べ替えられる
- 複数写真を選び、一括編集、移動、公開ができる
- 1枚選択と複数選択が混在せず、処理中は別アルバムへ移れない
- 選択Albumの全Photoを読み終えるまで更新・公開できず、Album一覧の件数を0件と確定表示しない
- 未保存の写真・Album情報を表示し、別対象へ移る前に破棄確認を行う
- `アルバムを公開`または`変更を公開`で、Albumと対象Photoをまとめて公開できる
- Album情報の保存失敗時は写真公開を開始せず、Photoを先、Albumを最後に公開する
- 部分失敗を完了と表示せず、Albumを含む失敗対象と理由を確認し、失敗分だけ再実行できる
- 並べ替えの部分失敗時は、保存済みの位置を元へ戻す
- 要確認フィルターと検索を併用できる
- Organizerから追加した写真は位置情報確認が終わるまで、Organizer、標準Photo編集、公開予約のいずれからも公開できない。未確認原本のダウンロードを拒否し、派生画像失敗時にも原本を代替表示しない
- AlbumsとPublic Photosの標準画面から対象Organizerへ1操作で移動でき、Album編集には状態別件数と最大24点のサムネイルを表示する
- 公開サイトに管理UIが残らず、写真ホストの管理APIは404、公開Media読取だけはGET／HEADで利用できる
- 旧`/studio/*`は404になり、旧管理Cookieでは編集権限を得られない
- Mediaの原本一覧、位置情報除去、キャッシュ、公開URLに回帰がない。旧Studioだけにあった高度なMedia診断は廃止対象として扱う
- PCと390px相当のモバイル幅、ライト／ダークで主要操作を確認し、モバイルのタブ切り替えと固定見出しを確認する
- 数千点のPhoto索引を100件ずつ読み、Album一覧の初期表示を全Photo読込で止めない
- Webテスト、Pythonテスト、型検査、production buildが合格する
