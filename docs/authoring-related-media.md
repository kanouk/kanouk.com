# 記事の関連アルバム・リンクカード・埋め込み

## 関連アルバムは記事の設定として保存する

EmDashの記事編集画面に「関連アルバム」を設ける。今回は任意のアルバム1件を選択する仕様とし、本文にアルバムカードを置くかどうかとは分けて扱う。

写真を挿入するときは、記事に設定したアルバムを最初に開く。未設定なら、従来どおり本文のアルバムカードを手掛かりにする。写真ごとに別のアルバムを選ぶこともできる。

関連の変更は記事の下書きに保存される。記事を公開するまで、アルバム側の「ブログ記事を読む」は公開中の設定を使う。関連を解除しても、本文のカード・写真・キャプションは削除しない。本文に明示したアルバムカードが残る場合、そのカードに基づく逆リンクも残る。

記事、アルバム、写真を自動で同時公開する機能はない。新しい設定への一括移行や、タイトル・カテゴリーからの関連推測も行わない。

## リンクカードは閲覧時に情報を補う

内部リンクは現在の公開済みデータを参照する。外部リンクは本文を先に表示し、その後に画像・タイトル・説明を取得する。取得に失敗しても、元のリンクと利用できる保存済み情報は残す。

取得結果はURL単位で24時間共有する。期限切れの情報は最大7日間表示を継続しながら更新し、失敗した取得は5分間再試行しない。同じURLの取得を12秒のロックでまとめ、実行環境ごとの同時取得を4件に制限する。

公開APIが受け付けるのは、公開記事・固定ページのIDと本文ブロックの識別子だけである。閲覧者による任意URLの指定は受け付けない。HTTPS、公開IPへの名前解決、リダイレクト回数、取得時間、HTML容量を検査する。認証情報を外部サイトへ転送しない。

編集画面で手動入力したタイトル・説明・画像を優先する。空欄は自動取得に任せる。自動値は `linkPreviewAuto` に分けて保存するため、再取得で手動値を書き換えない。既存カードで由来を判別できない値は手動指定として維持する。

## TikTok・SpotifyはURLとキャプションで挿入する

「TikTok / Spotify（キャプション付き）」ブロックで完全なURLを入力し、プレーヤーまたはリンクカードを選ぶ。記事独自のキャプションは、サービス側の説明とは別に保存する。

対応対象はTikTok動画と、Spotifyの曲・アルバム・プレイリスト・アーティスト・ポッドキャスト番組・エピソード。短縮URLには対応しない。短縮リンクをブラウザーで開き、移動先の完全なURLを使う。

編集画面・公開画面とも、ボタンを押すまでは公式プレーヤーを読み込まない。自動再生は有効にせず、元サービスへのリンクを残す。再生範囲、ログインの要否、削除済み・非公開コンテンツの案内は各サービスに依存する。サイト側からプレーヤー内部の状態を確実には判定できない。

## 本番の項目追加はバックアップ後に行う

既存データベースでは、seedの変更だけでは `posts.related_album` が追加されない。記事本文を変更せず、次のいずれかの方法で追加する。

管理画面を使う場合は、先にD1をバックアップする。管理者として記事編集画面を開き、「関連アルバム設定を有効にする」を押す。定義の追加と再確認が済んだら、未保存の編集がないことを確認してページを再読込する。項目が正しく用意されるまで、アルバム選択は無効になる。既存項目の定義が異なる場合は変更せず、画面に理由を表示する。

有効な管理者トークンがある場合は、対象を固定した補助コマンドも使える。

1. `python3 scripts/migration/backup_cloudflare_staging.py --d1-only --apply` でD1のバックアップを取得する。
2. `python3 scripts/cloudflare/run_related_album_schema_kanouk.py --dry-run` で、項目が未作成か、期待する定義と一致するかを確認する。
3. 同じコマンドに `--apply --backup-manifest <manifest.json> --receipt <新規の記録ファイル>` を渡す。バックアップの内容と対象を検証してから、未作成の項目だけを追加する。
4. 再度dry-runを実行し、`action: unchanged` を確認する。

項目追加には有効な管理者権限が必要。既存の定義が異なる場合は自動修正せず停止する。取り消す場合は、この任意項目を残したまま使用をやめられるため、記事データの削除やデータベース全体の復元は通常不要である。

EmDash管理画面への変更は固定バージョンの差分パッチで適用する。依存関係の更新で対象箇所が変わるとインストールを停止するため、更新時にはパッチを見直し、通常の記事作成・再編集を確認する。

ローカルの保存・公開テストは、開発サーバー起動後に `node scripts/verify-authoring-local-api.mjs --confirm-local` で実行する。このコマンドは127.0.0.1:4321に確認用の記事を作成し、外部の本番記事には書き込まない。
