# Yohaku design system

Yohakuは、カノログと公開写真アーカイブに共通する表示設計です。白と黒を基調に、装飾を減らすこと自体ではなく、読む・探す・写真を見る行為が静かに続くことを目的にします。元WordPress／SmugMugの機能と可読性を下回らないことを最低条件とし、単なるテーマ再現ではなく、移行後のほうが整っている状態を公開条件にします。

## タイポグラフィ

- 日本語本文・見出し・UIはNoto Sans JPに統一する。配信weightはRegular 400とSemiBold 600の2種に絞り、本文と見出しの差をサイズだけでなくweightでも明確にする。中間UIの500指定はブラウザが近い配信weightへ解決し、不要な日本語font subset取得を増やさない。
- 本文は約16–18px、行高1.92、最大39rem。長文で現在位置を見失わず、1行が長くなりすぎない幅にする。
- 日本語見出しはプロポーショナル詰めを無効にし、字間0.005–0.01em、行高1.42–1.52。大きさだけで階層を作らず、ウェイトと前後余白を併用する。
- サイト名は600、1rem、字間0.045em。キャッチコピーは400、0.66rem、字間0.075emで、ロゴと説明の役割を分ける。
- 見出しは最大でも約34pxを通常上限とし、長い日本語タイトルを巨大な塊にしない。
- 記事・固定ページ本文の見出しは本文サイズに対する比で決める。H2は1.33倍（左の縦線）、H3は1.17倍（下線）、H4は本文と同じ大きさ（文字幅の下線）。
- 本文以外の補助的な文字（件数、ラベル、カレンダー、ナビなど）は12px（`--text-micro`）を下限にする。例外はブランドのキャッチコピー、写真の通し番号、アルバムタイル名（11.5px以上）。
- 等幅フォントはコードの表示にだけ使う。件数や年は本文と同じ書体で、数字の幅をそろえる（`font-variant-numeric: tabular-nums`）。
- 見出し・ボタン・ナビなどの短い文言は文節で改行する（`word-break: auto-phrase`）。本文・箇条書きは文字単位の改行と強い禁則（`line-break: strict`）にする。URLや英数字の長い語は、はみ出す場合だけ折り返す（`overflow-wrap: break-word`）。
- 日の単位の日付は両サイトとも `yyyy/MM/dd`（例：2026/07/04）にそろえ、日本時間の暦で表示する。期間は `2026/06/07〜06/11`、年をまたぐ場合だけ終わりにも年を付ける。月の単位（アーカイブ）は「2026年7月」のままにする。読了時間は「N分で読む」にそろえる。
- 写真サイトの名前は「カノログ フォト」。ヘッダー・フッター・ページタイトルで同じ表記を使う。
- ログイン中のブログには、ヘッダーの上に細い管理バー（高さ2.25rem、スマホは2.75rem）を出す。左に管理画面・新規（記事・固定ページ・アルバム・写真を追加）・開いている記事や固定ページの編集、続けて一覧と写真整理など、右にユーザー名（設定・ログアウト）を置く。ログインしていない訪問者には出さない（出力しない）。固定ヘッダーとサイドバーの位置はバーの高さ（`--admin-bar`）だけ下げる。
- 写真サイトにも同じ管理バーを出す。ブログのログインは写真サイトから見えないため、ブログの管理バーが写真サイトに目印のCookie（`kanouk-admin-bar`、30日）を同じサイトとして置き、写真サイトはその目印がある時だけバーを出す（リンクはすべてブログの管理画面。管理画面側のログインが必要）。目印があるリクエストは共有キャッシュに入れない。アルバムと写真のページでは、そのアルバム・写真の編集と写真整理へ直接行ける。ブログでログアウトすると目印も消し、写真サイトのバーからも「このバーを隠す」で消せる。
- ヘッダーに検索の入力欄は置かず、「検索」リンクから検索ページへ移る（Cmd/Ctrl+Kでも同じ）。
- 日付・カテゴリー・読了時間のような並びは中黒で区切るが、中黒を行頭にも行末にも残さない。各項目が左の溝に中黒を持ち、行頭の溝は見えない位置に置く。

## グリッドと余白

- 4 / 8px系の段階的な余白を使い、近接・区切り・章の切り替えを同じ値にしない。
- 記事の上部メタ、タイトル、カバー画像、本文は同じ主軸へ揃える。著者・タグ等の補助情報だけを左レール、目次・探索機能を右レールへ分ける。
- ブログのページは、ホーム・一覧・記事・固定ページとも同じ2列（主列＋プロフィール列）にする。主列の左端はヘッダーのロゴにそろえ、記事本文は主列の中で44rem以内に収める。
- ヘッダーからページの最初の行までの距離は全ページ共通（`--page-top`）。ページ見出しは全ページ同じ段（`--heading-page`）。
- 記事の一覧（ホーム、すべての記事、カテゴリー、タグ、月別）は同じ行の形（左にサムネイル、日付・カテゴリー・読了時間、題名、抜粋）にそろえる。記事末尾の「続けて読む」は回遊用なのでカードのままにする。
- 68rem未満では右レール、48rem未満では左右レールを解除し、本文を一列にする。
- 枠のあるサイドバー（プロフィールなど）は、主列の最初のタイトルの文字の上端にそろえる。小さな日付やラベルの上端にはそろえない。
- フッターはブログと写真で同じ構造にする。左にサイト名と説明、中央にリンクのグループ、右にもう一方のサイトへのリンク（↗）と表示切り替え。狭い画面では縦に積む。
- 48〜68remではヘッダーが2段になる。固定ヘッダーが覆う高さは`--header-offset`で扱い、目次で移動した見出しや追従するサイドバーが隠れないようにする。
- 記事の目次は、狭い画面では常に、広い画面では9項目以上のとき、閉じた状態（「目次 N項目」）で始める。本文を最初の画面から読めるようにする。
- 罫線は境界がないと誤読する箇所だけに使う。画像直下、セクション見出し、画像なしカードに機械的な線を置かない。

## 画像

- トップと一覧のカバーは統一比率でトリミングし、カードのリズムを揃える。元画像そのものを見せる記事本文・写真詳細は縦横比を保持する。
- 寸法の小さい画像は本来の解像度を越えて拡大しない。余白が必要な場合は、サイト背景と区別できる静かなステージとして扱う。
- 画像がない記事にも同じ比率のYohakuプレースホルダーを置き、テキストだけのカードを別のレイアウトにしない。
- WordPress画像の指定幅、配置、キャプション、photo-frame／border／shadowの意味をPortable Textへ保持する。photo-frameは白い内縁、薄い境界、ごく弱い影で表現する。
- アルバムカバーと一覧はデザイン優先でcrop、写真詳細はcontain。写真上の前後移動、キーボード、swipe、全画面、共有、自動再生、download policyを維持する。

## 色と操作

- lightは紙#fcfcfaと墨#20211f、darkは#121318と#f1f1ef。藍のaccent（light #535fa8、dark #aeb7f0）はリンク、現在位置、意味のあるLucide iconに限定する。写真の暗いステージ上ではフォーカス色に明るい#bfc7ffを使う。
- アルバム一覧は正方形のタイル（最小11.25rem、mobileは2列）に、アルバム名を下部へ1行で重ねる。名前は11.5px以上とし、360px幅の画面でも通常の長さの名前が1行に収まるようにする。収まらない場合は末尾を省略する。小さい原本を一覧都合で拡大せず、低解像度coverはhover zoomからも除外する。
- アルバムの写真の下のキャプションは1行にし、収まらない場合は末尾を省略する（全文は写真ページ）。ファイル名だけのキャプション（IMG_4821.JPGなど）は一覧に出さない。
- 写真ページの暗いステージは、スマホでも画面の高さいっぱいに取る（写真の高さに縮めない）。
- アルバムページの見出しは、タイトル、1行のメタ（点数・撮影期間・表示範囲）、説明、静かな文字リンク（「ブログ記事を読む」「地図で見る」）の順に一つのまとまりとし、その直後から写真を並べる。記事リンクには記事タイトルを出さない。関連記事が複数なら（1）（2）と番号を付け、記事タイトルはtitle属性と読み上げ名にだけ使う。ページ送りは写真の下だけに置く。
- 引用は`yohaku.quote`で本文、複数段落、箇条書き、inline mark、出典を一つの意味単位として保持する。本文と同じ文字サイズ・行間を使い、淡い面、accentの左線1本、控えめなQuote iconで本文との差を示す。
- 操作対象は原則44px相当の高さを確保し、hoverだけでなくkeyboard focusを明示する。
- motionは内容理解を助ける短い変化だけにし、`prefers-reduced-motion`を尊重する。

## 公開前の合格条件

1. 320 / 390 / 768 / 1024 / 1440pxで、タイトル、画像、本文、メタ情報の基準線と余白を実画面確認する。
2. featured imageあり／なし、横長／縦長／小解像度、長い日本語タイトル、photo-frame本文画像、Pochipp商品画像あり／なしを確認する。
3. すべての操作をkeyboardで実行でき、主要操作のtouch target、focus、dark mode、200%拡大で破綻しないことを確認する。
4. 元ブログ／SmugMugの代表ページと並べ、機能欠落、画像の過拡大、不要な余白・罫線、読みにくい字詰めがないことを確認する。

参考: [Apple Typography](https://developer.apple.com/design/human-interface-guidelines/typography)、[Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout)、[WCAG 2.2](https://www.w3.org/TR/WCAG22/)。数値をそのまま模倣せず、Web上の日本語長文と写真閲覧に合わせて適用します。
